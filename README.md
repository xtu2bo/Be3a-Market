# بيعة | Be3a Market

متجر مصري عربي RTL للملابس النسائية والشنط، مع لوحة إدارة وقاعدة بيانات D1 ورفع صور R2. مبني بـ React / Vinext / Cloudflare Workers.

## الاستخدام

- المتجر: `/`
- الإدارة: `/admin`، عبر صفحة دخول مستقلة. أول مرة اختاري تأكيد الحساب المصرّح له ثم أنشئي كلمة مرور من 10 أحرف أو أكثر؛ بعد ذلك يمكن الدخول بالإيميل `be3amarket@gmail.com` وكلمة المرور.
- من المنتجات: أضيفي الصورة الحقيقية والاسم والوصف والقسم والسعر والمقاسات والألوان والمخزون. اختاري «ظاهر في المتجر» ثم احفظي.
- من الإعدادات: عدّلي البانر واللوجو والنصوص والتواصل والأقسام والشحن والسياسات. فعّلي استقبال الطلبات بعد مراجعتها.
- المخزون إجمالي لكل منتج عبر المقاسات والألوان؛ لإدارة كميات منفصلة أضيفي كل تنويعة كمنتج مستقل حاليًا.
- من الطلبات: تأكيد، شحن، تسليم أو إلغاء قبل الشحن. الإلغاء يعيد المخزون مرة واحدة. تصدير CSV لأحدث 500 طلب.
- لوحة الإدارة تعرض زيارات الأسبوع (وتظهر `+999` بعد تجاوز 999) وعدد طلبات الأسبوع، وتنبه داخل اللوحة وعبر إشعار المتصفح عند وصول طلب جديد أو انخفاض مخزون منتج. صفحة `/admin/notifications` تجمع كل التنبيهات.
- الأقسام الإضافية `/admin/team` للمشرفين والصلاحيات، `/admin/coupons` للكوبونات، `/admin/categories` للأقسام، `/admin/shipping` للمحافظات وأسعار التوصيل، و`/admin/analytics` لتقارير الشهر الحالي والسابق و7/30/90/365 يومًا برسوم للمبيعات والزيارات. حالات الطلب تشمل المرتجع، وتظهر نافذة تأكيد قبل عمليات الحفظ والحذف وتغيير الحالة وتشغيل/إيقاف استقبال الطلبات.
- اللغة والثيم يتغيران من الأزرار الموجودة داخل فوتر المتجر وشريط لوحة الإدارة؛ العربية هي الافتراضية والإنجليزية تغيّر النصوص الأساسية واتجاه الصفحة.
- إخفاء المنتج يحفظه مع تاريخ الطلبات ويسمح بإعادة إظهاره.
- الطلبات بالدفع عند الاستلام. زر واتساب يفتح محادثة متابعة، ولا يرسل رسائل تلقائيًا.

## وضع البداية

استقبال الطلبات مغلق، مناطق الشحن فارغة، ولا توجد منتجات أو طلبات فعلية. تظهر نماذج إرشادية عند خلو الكتالوج وإغلاق الطلبات. الأسعار والصور الحالية قابلة للاستبدال من لوحة الإدارة. الصور والمعلومات الحقيقية وسياسات المتجر يضيفها صاحب المتجر.

## حدود المجاني والنشر

لم تُشترَ باقة أو دومين أو بوابة دفع. أول نشر عبر Sites خاص بصاحب الموقع، ولا يُعد إطلاقًا عامًا للعملاء. إتاحة رابط عام وخيارات المنصة تخضع لحساب صاحب الموقع وصلاحياته؛ تكلفة Sites لا تُستنتج من تسعير Cloudflare المباشر.

للنقل مستقبلًا لحساب Cloudflare مستقل: Workers وD1 لهما خطط مجانية محدودة، وR2 له حصة مجانية مع فوترة محتملة عند التجاوز. لا نفترض أن استضافة غير محدودة أو دومين خاص مجاني. راجعي الخطط الرسمية بتاريخ التنفيذ 14 سبتمبر 2026:

- https://developers.cloudflare.com/workers/platform/pricing/
- https://developers.cloudflare.com/d1/platform/pricing/
- https://developers.cloudflare.com/r2/pricing/

لا تنشري هذا البناء مباشرة خارج Sites مع الوثوق بهيدرات الهوية: تسجيل الدخول يعتمد على بوابة Sites التي تتحقق من الهوية. النقل المستقل يتطلب إعداد مصادقة موثوقة والتحقق من رمزها في السيرفر أولًا.

## التطوير والتحقق

Node 22.13+، ويفضل 24 LTS. `npm run install:ci` ثم `npm run dev`. `npm run build` لإنشاء Worker. في Windows تم تشغيل `node scripts/run-framework.mjs build` بسبب مشكلة شيم npm في غلاف Sites المحلي.

المخطط: `db/schema.ts`، الهجرة الأولى: `drizzle/0000_cool_spyke.sql`. الهجرة تحتوي triggers ذرية لحجز واسترجاع المخزون. لا تعيدي تعديل الهجرة بعد نشرها. إضافة تغييرات لاحقة تكون بهجرات جديدة.

اختبارات:

- `node node_modules/typescript/bin/tsc --noEmit`
- `node scripts/test-orders.mjs`: قاعدة SQLite مؤقتة، مخزون، منع زيادة البيع، السعر والمقاسات، التراجع الذري والإلغاء.
- `node scripts/test-api.mjs`: اختبار محلي فقط على `localhost:5173` مع قاعدة مهيأة؛ ينشئ بيانات اختبار محلية ويطبع معرّفات التنظيف. لا يُشغّل على الإنتاج.
- `node scripts/test-upload.mjs`: رفع/قراءة صورة محلية ورفض SVG، يترك صورة اختبار في تخزين المعاينة المحلي فقط.

تم التحقق من APIs وتصيير الصفحات HTTP. لم يتم إجراء اختبارات نقر أو فحص بصري داخل المتصفح. أداة WebMCP لتصفية المنتجات تُفعّل عند توفر API المتصفح؛ لم تتوفر بيئة تحقق WebMCP معتمدة، فلا يُدّعى اختبار تسجيلها وتنفيذها.

## حماية البيانات

تفويض الإدارة في السيرفر، التحقق من Origin للتغييرات، prepared statements، تحقق الحقول، صور PNG/JPEG/WebP فقط، حساب الأسعار والشحن في السيرفر، معرف طلب UUID لمنع التكرار، تحديد معدل الطلبات، وتحديث مخزون ذري مع رفض حفظ تعديل قديم فوق طلب جديد. البيانات الأساسية محفوظة في D1 والصور المرفوعة في R2. localStorage للشنطة المؤقتة والمفضلة فقط.

## الأصول

اللوجو المرجعي من المستخدم، ويُعرض من نسخة شفافة مخصصة للهيدر حتى يظل واضحًا داخل الشريط المثبت وعلى الثيم الداكن. الصور الموجودة في `public/images` صور افتتاحية قابلة للاستبدال من لوحة الإدارة.

## التوسيع الأخير

المتجر أصبح متعدد الصفحات: `/shop`، `/category/اسم-القسم` (اسم القسم الفعلي مرمّز داخل الرابط)، `/product/id`، `/cart`، `/checkout`، `/favorites`، `/about`، `/contact`، `/shipping`، `/privacy`، `/returns`. للإدارة صفحات `/admin/products` و`/admin/orders` و`/admin/settings`.

صفحة المنتج تدعم الصورة الرئيسية و8 صور إضافية، المقاسات، الألوان، المفضلة، تفاصيل الشحن والاسترجاع، ومنتجات مقترحة. الكتالوج يدعم البحث والفرز والتصفية بالمقاس واللون وأقصى سعر. إضافة صور المعرض والأغلفة والبنر الإضافي متاحة من الإدارة. هذه الإضافات محفوظة في JSON القائم ولا تحتاج تغيير مخطط قاعدة البيانات.

حركات 2D عبر CSS وIntersectionObserver: ظهور تدريجي عند التمرير، حركة خفيفة لصورة البانر، شريط عبارات متحرك، زخرفة دوارة، تفاعل كروت وأزرار، عداد الشنطة وشريط تقدم التمرير. احترام `prefers-reduced-motion` وزر إيقاف الحركة في أسفل الموقع. لا مكتبات أنيميشن إضافية. المحتوى ظاهر افتراضيًا بدون JavaScript.

`node scripts/test-routes.mjs` يتحقق من 19 رابطًا وصفحات الإدارة والروابط غير الموجودة. لم تُجرَ اختبارات تفاعل/لقطات داخل متصفح؛ التحقق شمل بناء الإنتاج وTypeScript وHTTP وواجهات API واختبارات ذرية المخزون.
